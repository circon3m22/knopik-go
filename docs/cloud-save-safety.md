# KNOPIK GO — безопасные облачные сохранения

## Что изменилось

KNOPIK GO сохраняет прогресс **только** в `public.knopik_go_saves`. KNOPIK TAP использует другую таблицу `public.game_saves`; изменение одной игры не затрагивает другую. Идентификатор профиля `Foma` и действующие политики ограниченного доступа GO не меняются.

Клиент читает `revision`, пишет через `public.save_knopik_go_progress(new_save, expected_revision, save_source_id)` и принимает успешное сохранение только при подтверждении **точного содержимого, нового номера ревизии и источника**. Сохранение с устаревшей ревизией возвращает серверную версию и блокирует автоматическую перезапись. Простой вход, синхронизация сессии и обновление токена не создают нового прогресса.

Клиент держит последний несинхронизированный снимок в LocalStorage с номером облачной ревизии, автоматически отправляет его при восстановлении сети и повторяет записи с экспоненциальной паузой. Большое число событий Knopik Run не переносит сохранение бесконечно: запись запускается по ограниченному интервалу. При конфликте версия устройства может быть скачана и, **только после явного подтверждения**, загружена вместо облачной. Перед изменением облачные состояния архивируются.

Если сервер не вернул актуальное сохранение или версия данных выше поддерживаемой, игра блокирует загрузку вместо сброса или импорта из TAP. Старое локальное сохранение, отличающееся от облачного, не уничтожается без решения пользователя.

## База данных

- `private.knopik_go_save_history` — закрытый журнал: начальная копия действующих сохранений и автоматический снимок **до каждого UPDATE/DELETE**; отдельный от аналогичного журнала TAP.
- `private.archive_knopik_go_save()` — триггер истории.
- `public.save_knopik_go_progress(jsonb,bigint,text)` — транзакционный CAS, работает с текущим `auth.uid()` и прежними RLS, не предоставляет прав других игроков.
- `private.require_knopik_go_revision()` — запрещает прямые старые обновления, не увеличивающие ревизию ровно на единицу (активировать вместе с обновлённым клиентом).

## Награды

`claim_knopik_go_daily_case` и `redeem_knopik_go_promo_code` изменяют сохранение на сервере и увеличивают ревизию. Клиент завершает отложенную синхронизацию **до** начисления награды, затем обновляет облачную ревизию. Это предотвращает повторное применение устаревшей локальной копии поверх выданных наград.

## Ограничения

LocalStorage может быть очищен пользователем или браузером; Supabase подтверждает факт сохранения только после успешного ответа. Архив не восстанавливает состояния, уничтоженные **до** установки защитного триггера. Проверять работу после публикации следует на последней сборке и с одинаковым аккаунтом; старые открытые вкладки необходимо обновить.
