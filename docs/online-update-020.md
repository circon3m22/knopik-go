# ONLINE UPDATE 0.2.0 · 16.10.2026

Официальная нумерация: `версия.обновление.патч`. Первый выпуск — `0.1.0`, этот выпуск — `0.2.0`. Прежние v62–v64 в AGENTS.md обозначают рабочие этапы, а не публичные версии. История для игроков находится в `app/game-releases.json`; этот файл задаёт текущую версию интерфейса.

## Выпуски и анонс

Версия видна в стартовом меню и настройках. История в настройках сворачивается, содержит описание 0.1.0 и 0.2.0. Сообщение «Игра обновлена до версии…» появляется один раз на установленную версию, исчезает через 8 секунд, закрывается крестиком/касанием игры и не ставит её на паузу. Смена worker, отсутствие сети и старый кеш не вызывают сообщение повторно. При запрете localStorage сообщение не показывается, чтобы не повторяться каждый запуск. Отметка общая для GO/Run в этом браузере.

Будущие изменения: `npm run release -- patch --title "Название" --change "Описание для игроков"` (либо `update`, либо `version`). Команда одновременно меняет каталог, package.json и обе корневые версии lockfile. `--dry-run` проверяет следующий номер без записи. Для каждого нового выпуска обязательно добавить описание; сами исправления тоже должны войти в коммит. Тест проверяет согласованность версий. Публичный номер меняется на выпуск, а не на техническую пересборку того же кода.

`npm run announcement:online` воспроизводит SVG и PNG 2160×2160/1080×1080 в outputs/announcement. Используются реальные PixelLogo/AnimatedAdventureKnopik и KnopikAnimator. Белая сиба с шляпой/банданой, рыжий Кнопик с ирокезом/очками и чёрная сиба с плащом. Ступенчатый сине-фиолетовый фон, пиксельные надписи путями; без внешних шрифтов, растровых вставок и генерации фотографий. Исторический генератор намеренно закреплён за 0.2.0.

## Отзывчивое совместное движение

Причина рывков: предыдущий клиент каждые 80 мс восстанавливал гостя в отстающую позицию ведущего, прибавлял оценку половины RTT и затем притягивал к ней текущее движение. При остановке или повороте старые координаты противодействовали стику; кувырок ожидал ведущего.

Гость теперь управляет своим перемещением локально, включая начало кувырка. Ведущий получает историю до 48 точек, записанных максимум около 60 раз в секунду, вместе с обычным вводом каждые 50 мс. Координаты в пути округлены до сотых, чтобы уменьшить трафик. Повтор точек помогает переживать потери и перестановку пакетов, а промежуточные точки сохраняют обход углов. Ведущий не интегрирует такое движение второй раз. Проверяется структура, монотонные номера точек, ограниченный бюджет расстояния с запасом на джиттер и каждый участок пути через существующие коллизии. Некорректный путь вызывает коррекцию с номером ревизии; старые пакеты до получения этой коррекции не запускают новые коррекции. Здоровье, урон, противники, предметы, задачи и победа по-прежнему принадлежат ведущему.

Снимки не перезаписывают локальные координаты/угол/ходьбу/таймеры кувырка при обычном движении. Падение, поднятие, недопустимая геометрия и новая ревизия возвращают состояние ведущего. Отключение и общая пауза сохраняются. Поле `motionVersion: 1` согласует возможность сразу с первого снимка; основной протокол Supabase 3 и SQL-схема не изменены. С прежним клиентом без этой возможности остаётся прежний способ синхронизации. Для нового поведения следует обновить игру на обоих устройствах.

Движение удалённых сущностей интерполируется по очереди снимков с задержкой 120 мс и ограниченным продолжением до 80 мс, чтобы каждый новый пакет не начинал интерполяцию заново. Ведущий сглаживает видимую позицию напарника отдельно от координат, используемых для боя и коллизий. Это обмен точности одновременного отображения на отзывчивое локальное управление, как попросил пользователь; фактический сетевой RTT не снижается.

## Скины и управление

TapOutfitArt получал одежду, но не скин: тело оставалось рыжим за перекрашенной головой. Теперь туловище использует ту же палитру, а глаза — отдельные палитры для белой и чёрной сиба-ину, включая спокойное/уставшее/сердитое выражение. Цвета одежды, зелёное усиление и лазеры сохранены.

Обе кнопки ранее имели класс adventure-interact и попадали в одну и ту же ячейку общей сетки управления. Теперь действие/удерживаемая помощь и волна плаща находятся внутри одного элемента сетки, в разных колонках; у плаща собственный класс. Для низкого горизонтального экрана заданы отдельные строки стика, вспомогательных кнопок и боя. Удержание E/помощи и нажатие Q/волны независимы.
