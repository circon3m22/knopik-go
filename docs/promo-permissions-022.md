# Промокоды GO · 0.2.2

Ошибка воспроизведена непосредственно как роль authenticated с UUID разрешённого игрока: `permission denied for schema private`, SQL-функция redeem_knopik_go_promo_code падает during startup. Публичная SECURITY INVOKER-обёртка содержала строковое SQL-тело, которое обращалось к private-схеме при каждом вызове. У браузерной роли нет USAGE на эту схему, хотя EXECUTE на обе функции уже был выдан.

Исправление: SQL-standard `BEGIN ATOMIC` связывает вызов существующего private-helper при создании функции. Публичная обёртка остаётся SECURITY INVOKER с пустым search_path. Не выдавались широкие права на private-схему или таблицы, не менялись проверка GO-доступа, административные ограничения, блокировки кода/сохранения, сумма награды и одноразовое использование. Контракт RPC не изменился: серверное исправление действует и для уже открытой игры. Базовый установочный SQL docs/separate-go-schema.sql тоже исправлен.

Миграция fix_go_promo_invoker_gateway применена в uxxzvjwsexdoqcevzipu; файл 20261016083456 совпадает с удалённой историей. Повторно не применять. Исходник — scripts/go-promo-gateway.sql.

scripts/qa-go-promo.sql выполнен в настоящей БД через public RPC под ролью authenticated, а не только postgres. Временный случайный код начислил 317 монет, ревизия сохранения выросла на один, повтор дал «уже использован» без второго начисления. Проверены неверный формат, отсутствующий код, запрет другого GO-недопущенного UUID и анонимного вызова, отсутствие USAGE на private, отсутствие изменений остальных полей прогресса, других GO-сохранений и TAP. Вся транзакция откатилась, включая код, начисление и историю; реальные коды не использовались.

35 обязательных файлов Pages прошли, TypeScript и статическая сборка прошли. Клиентская логика наград не изменялась, дополнительных зеркальных unit-тестов SQL нет: регрессия проверена реальной ролью и сохранённым SQL-сценарием. Браузер/два физических устройства не проверялись. Актуальные Supabase changelog и docs о функциях/правах просмотрены; релевантных изменений API нет, а объявление о старых TLS-шифрах не требует изменения этого исправления.
