# Анонс и загрузка ARCADE UPDATE · 0.3.1

Пользователь попросил квадратный анонс в прежнем стиле, новое меню загрузки в стиле анонса и новое оформление при каждом следующем выпуске.

Анонс обновления 0.3.0 собран из нативных SVG игры: PixelLogo, три AnimatedAdventureKnopik с реальными скинами/одеждой, CocoaMachine, PlinkoBoard, карты, кости и шесть DetailedPotion. Ступенчатый сине-фиолетовый фон, точечные звёзды, светлая пиксельная типографика, дата16.10.26. Надписи собраны путями, без зависимости от установленного шрифта. Нет генерации изображений или фотографии. Каждый персонаж имеет собственные SVG ID; все внутренние ссылки разрешаются.

`npm run announcement:arcade` воспроизводит:

- outputs/announcement/knopik-go-arcade-update-0.3.0.png — 2160×2160;
- outputs/announcement/knopik-go-arcade-update-0.3.0-1080.png — 1080×1080;
- outputs/announcement/knopik-go-arcade-update-0.3.0.svg;
- public/release-artwork/arcade-030.svg — тот же оригинал для игры, около110KB.

Постер ARCADE UPDATE сохраняет номер тематического обновления0.3.0. Выпуск оформления — патч0.3.1; действующий номер игры отдельно показан в загрузке и меню. История/тихое уведомление используют настоящий номер0.3.1.

## Оба экрана

GameLoadingScreen (ожидание аккаунта/сохранения) и GameLaunch (подготовка офлайн-пакета и запуск) используют один ReleasePoster и одну палитру из release-presentations.json. SVG загружается eagerly с высоким приоритетом, имеет заранее заданное соотношение1:1 и попадает в полный offline-pack. Сцена не запускает игровой движок/RAF/звуки. Небольшие мерцания SVG и неопределённый индикатор учитывают reduced motion.

При проверке аккаунта нет выдуманного процента. Процент/байты в GameLaunch по-прежнему берутся из реального офлайн-пакета; 100% и «Играть» появляются только при ready. Ошибка/неподдерживаемый браузер сохраняют повтор и «Играть онлайн». Установка, инструкция Safari/Android, подтверждение appinstalled и вход в кооператив сохранены. Звук по-прежнему разблокирует реальная кнопка пользователя.

На телефоне постер над действиями, в широком/ландшафтном режиме — слева от действий. Высота постера ограничена доступной высотой; короткий экран и развёрнутые инструкции могут прокручиваться. Safe-area, цели нажатия от44px, контраст и клавиатурный фокус сохранены. Старую сцену квартала не нужно возвращать в новые загрузки.

## Правило для всех следующих выпусков

Это постоянное требование пользователя: **каждый новый выпуск получает новый анонс и новое меню загрузки в его стиле**, включая патчи. Не ограничиваться сменой номера или палитры.

1. Собрать новый SVG из графики соответствующего обновления и отдать PNG1:1; визуально проверить экспорт.
2. Положить SVG в public/release-artwork под новым именем; проставить уникальный data-release-art.
3. Добавить отдельную запись в app/release-presentations.json: уникальный id, introducedIn с точной будущей версией, edition с номером тематического обновления, title/alt/подсказки/палитра/путь к SVG.
4. Выполнить обычный `npm run release -- patch|update|version --title ... --change ...`. Можно явно указать `--presentation новый-id`; иначе запись выбирается по introducedIn.
5. Команда откажет в записи версии без нового оформления, с оформлением старой версии или с байтовой копией прежнего SVG. Dry run остаётся доступным без арта и возвращает needsPresentation:true.
6. Тесты проверяют связь последнего выпуска с оформлением, квадратный SVG, ID/ссылки, отсутствие внешних картинок/скриптов, одинаковый арт обоих экранов и отказ переиспользования при выпуске.

Это требование к реализации, а не запрос подтверждения: сначала подготовить новый анонс и меню, затем продолжать разрешённую публикацию.
