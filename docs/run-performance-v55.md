# Run v55: пауза, частота кадров и отрисовка

У прежнего RunnerFrameBudget была эвристика: после 24 дорогих кадров при средней стоимости выше 12 мс отрисовка ограничивалась 30 FPS. Даже кадр 13–16 мс мог вызвать это ограничение; возвращение требовало длительной серии дешевле 9 мс. В v55 отрисовка следует каждому завершённому шагу физики, без этого ограничения. Сама симуляция сохраняет фиксированные 60 Гц.

Автоматический режим меняет только плотность Canvas/WebGL. Начальная плотность — min(DPR, 2), затем возможны 1.5 и 1. Решение использует сглаженную стоимость подготовки и интервал показанных кадров: второй показатель замечает задержки GPU, отсутствующие в измерении JavaScript. Первые 30 кадров прогревают измерение, снижение требует 24 тяжёлых кадра; между снижениями есть 90 кадров стабилизации. Возвращение требует 360 лёгких кадров, между повышениями — 180 кадров. Пауза исключается из измерения интервалов. Выбор «Чётко» сохраняет DPR экрана до 4, «Быстро» фиксирует плотность min(DPR, 1). Разрешение интерфейса не меняется.

При DPR 3 начальный автоматический кадр имеет на 55.6% меньше пикселей, чем прежний полный DPR. Это сравнение числа пикселей, не измерение ускорения GPU. Дальность 600, геометрия, окна, текстуры, погода, частицы, десять районов, коллизии и начисления не сокращены. Режим сохраняется в Save v29.

Проецируемые дороги, стены, крыши и боковые окна передают численные полигоны виртуальному SVG-узлу. WebGL использует их без сериализации и обратного разбора строки. Для Canvas/SVG строка строится при обращении к `d`. Удаление/замена атрибута инвалидирует численные данные; неизменённые координаты сохраняют идентичность кеша. Схлопнутые вершины у ближней плоскости нормализуются тем же допуском, что в старом парсере. Дополнительно кешируются метаданные отсечения и локальные обводки, прямоугольные обводки используют точные смещения без нормализации векторов; наследование оформления обходится без Object.assign на каждом узле.
